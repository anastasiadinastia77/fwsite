# FW LABEL NETWORK — MVP 0.1

Интерактивный русскоязычный прототип музыкальной платформы. Это демонстрация: реальные заказы, платежи, Telegram, загрузка на сервер и аналитика отключены. Все эксперты вымышлены.

## Как запустить

Нужны Node.js 22.12+ (проверено на 24) и npm.

Откройте терминал в папке проекта и выполните:

```bash
cd /workspace/fwsite
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

Первая команда переходит в проект, вторая устанавливает зависимости по зафиксированному списку, третья запускает сайт. Если зависимости уже установлены, достаточно третьей команды. Терминал оставьте открытым; Ctrl+C останавливает сервер.

В локальной среде откройте адрес, который напечатает Vite. В облачной среде используйте панель предпросмотра/портов редактора и откройте порт **5173**, если такая панель доступна. В интерфейсе настройки облачной среды предпросмотр может отсутствовать: не публикуйте окружение в расчёте получить публичный сайт. Публикация самого сайта не выполнялась.

## Что попробовать

1. Нажмите «Выбрать эксперта», переключите жанр и откройте демо-профиль.
2. Выберите разбор за 1 990 ₽. Введите вымышленные данные.
3. Нажмите «Симулировать оплату». До этого шага выбор файла недоступен.
4. Выберите тестовый MP3/WAV. На устройстве читаются только имя и размер: файл не отправляется, не воспроизводится и не сохраняется.
5. Симулируйте передачу и голосовой разбор. Плеер — визуальный макет без записи.
6. Задайте один или два вопроса. Повторная отправка в этом заказе недоступна. Покажите демо-ответ и откройте премиальные возможности.

В реальном сервисе вопросы будут доступны в течение 72 часов после отзыва. Здесь это только подпись, без таймера. Данные живут в памяти страницы; закрытие заказа или обновление страницы сбрасывает демо. Новый заказ — новая демонстрация. UTM-метки не реализованы.

## Проверки

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

`typecheck` проверяет типы данных, `lint` — правила кода, `test` — переходы этапов и жанры, `build` собирает готовую версию в `dist`. `test:e2e` открывает настоящий браузер и проходит весь демо-заказ, проверяет мобильный экран и отсутствие внешних запросов/POST при сценарии. Браузерные проверки настроены на Chromium в `/usr/bin/chromium` в этой облачной среде. На другом компьютере настройте `executablePath` в `playwright.config.ts` или используйте браузер Playwright. Снимки экранов создаются в `artifacts/` и не включаются в Git.

## Устройство проекта

- `src/main.tsx` — лендинг, каталог, модальные окна, оформление и демо-заказ.
- `src/data.ts` — вымышленные эксперты, жанры и последовательность этапов.
- `src/style.css` — оформление и адаптация под телефон.
- `src/data.test.ts`, `e2e/demo.spec.ts` — автоматические проверки.

Выбран React + TypeScript + Vite: для этого прототипа без сервера это проще Next.js. Разделы главной доступны по якорям, профиль и заказ открываются в окнах; отдельных маршрутов пока нет. Платёжных и Telegram SDK, серверного API и внешних шрифтов нет. Внешние сервисы и ключи не требуются.

Сроки будущего сервиса и цены премиальных услуг предварительные. Подключение реальной оплаты, бота, хранения и публичное размещение — отдельный этап после согласования.

## Тестовый сайт на GitHub Pages

В `.github/workflows/pages.yml` настроена автоматическая проверка, сборка и публикация при отправке изменений в `main`. В GitHub → Settings → Pages → Source выберите **GitHub Actions**. Ход публикации виден во вкладке **Actions**, процесс **Publish FW LABEL NETWORK**.

Ожидаемый адрес после успешной публикации: https://anastasiadinastia77.github.io/fwsite/

Для Pages сборка использует `npm run build -- --base=/fwsite/`, чтобы файлы оформления и JavaScript открывались по правильному пути. Обычная локальная сборка по-прежнему доступна через `npm run build`. Сайт публичный; никаких реальных заказов и оплат нет.

Правила оформления, читаемости и адаптации сайта сохранены в [DESIGN.md](DESIGN.md). Они служат ориентиром для дальнейших изменений интерфейса.

Актуальное визуальное направление — плакат музыкального медиа: тёплый светлый фон, крупные узкие заголовки Oswald Bold, чёрный текст и оранжевая ценовая полоса. Oswald поставляется локально из `@fontsource/oswald`, включая кириллицу; запросов к Google Fonts нет. Фото и имя артиста из референса не используются.
