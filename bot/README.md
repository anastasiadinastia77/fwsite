# Пилот Telegram-бота

Аватарка бота: [`public/brand/fw-bot-avatar.png`](../public/brand/fw-bot-avatar.png). Это отдельный квадратный знак FW со стрелкой в цветах сайта, подготовленный для круглого кадрирования Telegram. Установить его можно у владельца бота через @BotFather → `/setuserpic` → @FWLablebot → отправить PNG как фото. Сохранение файла в репозитории само по себе не меняет фотографию профиля.

Это отдельная серверная часть, готовая к подключению и проверенная без сети. Реальный бот пока не подключён. Сайт на GitHub Pages остаётся демо: кнопки сайта не создают серверные заказы. Для пилота оператор вручную регистрирует согласившихся экспертов, создаёт заказ и подтверждает поступление оплаты. Никаких имён артистов из каталога бот автоматически не подключает.

## Что уже работает в коде

Вход по ссылке открывает одну карточку разбора: эксперт, статус и доступные действия. Кнопки «Меню», «Мои разборы» и «Мои задания» дают навигацию без ввода команд. Обновление статуса и выбор услуг редактируют текущую карточку. Если карточка удалена, бот создаёт новую в том же чате; неизменившаяся карточка не блокирует доставку. Повторное открытие использованной ссылки возвращает пользователю его собственные заказы. Внутренние ID заказов в карточках не показываются. Демо отмечено одной короткой подписью; оплата по тестовым заказам по-прежнему не записывается.

1. Клиент подключает заказ по персональной одноразовой ссылке. Эксперта заранее назначает оператор по Telegram ID; выбрать себе роль эксперта нельзя.
2. До подтверждения оплаты трек эксперту не доступен. Подтверждение возможно только из серверной консоли оператора, после проверки фактического поступления денег. Клиентская команда, скриншот или кнопка оплатой не считаются.
3. Эксперт открывает `/orders`, выбирает заказ и записывает голосовой разбор. Бот отправляет запись клиенту без пересылки профиля эксперта.
4. После успешной отправки записи в Telegram отсчитываются настоящие 72 часа. Клиент отправляет один раунд до пяти вопросов: текстом (по вопросу на сообщение) или одним голосовым. Текст ограничен 1 000 знаков на вопрос и 3 000 на весь раунд, чтобы карточка помещалась в сообщение Telegram. Для голосового правило «до пяти вопросов» указано в подсказке; распознавание речи и автоматический подсчёт озвученных вопросов не подключены. Можно сразу нажать «Всё понятно».
5. Эксперт отвечает одним голосовым или текстовым сообщением на весь раунд. Затем нажимает «Завершить разбор». Если клиент ничего не прислал, завершение доступно после истечения 72 часов.
6. Эксперт выбирает «Готов к отправке» или «Нужна доработка», до двух дополнительных услуг и необязательный комментарий. Для личного представления лейблам требуется отдельное подтверждение эксперта. Перед отправкой есть предпросмотр. Можно закончить без предложения услуг.
7. Клиент по желанию нажимает «Узнать условия». Эксперт получает запрос; оператор видит его через `requests` и согласует условия в уже установленном канале связи с клиентом. Новая оплата и переписка по следующей услуге пока не автоматизированы.

Для демонстрации без бота, токена, настоящих людей и оплаты:

```bash
npm run bot:demo
npm run test:bot
```

Это текстовый прогон с вымышленными Telegram ID и голосовыми файлами, а не подключение к Telegram.

## Создать бота без установки программ

1. Открой в Telegram официальный [@BotFather](https://t.me/BotFather).
2. Отправь `/newbot`, задай отображаемое имя и свободное имя, заканчивающееся на `bot`.
3. Сохрани выданный токен. В переписку, GitHub и браузерный код его не вставляй. В чат разработки достаточно прислать имя бота вида `@имя_bot`.
4. В панели выбранного сервера добавь токен как секрет `TELEGRAM_BOT_TOKEN`, имя без `@` как `TELEGRAM_BOT_USERNAME`. `BOT_BRAND` задаёт название проекта в приветствии; его можно сменить независимо от кода. `BOT_ENABLED=true` разрешает реальное подключение. Пока готовишь — оставь `false`.
5. Клиент и эксперт должны сами открыть бота и нажать Start: бот не может первым начать разговор с пользователем. Согласившийся эксперт пишет нашему боту `/id` и передаёт показанный числовой Telegram ID оператору для подключения. Имя `@username` не заменяет числовой ID. Команда `/id` не даёт доступ к чужим заказам.

Токен один на весь проект. Не нужно создавать отдельного бота каждому эксперту. Выбранный владельцем username: **[@fwlablebot](https://t.me/fwlablebot)**; значение `TELEGRAM_BOT_USERNAME` — `fwlablebot`, без `@`. При выборе нового бренда можно поменять отображаемое имя через BotFather; выбор окончательного username лучше сделать до рассылки ссылок.

После безопасного добавления токена сначала выполни `npm run bot:check`. Эта проверка вызывает только `getMe` и `getWebhookInfo`, проверяет совпадение username и не отправляет сообщений, не удаляет webhook и не запускает обработку заказов. Она работает и при `BOT_ENABLED=false`. Сам запуск бота тоже проверяет username, чтобы случайный токен другого проекта не начал обрабатывать его сообщения.

## Сервер и запуск

GitHub Pages не запускает серверные процессы. Нужен постоянно работающий сервис **Node.js 24**, одна реплика, исходящий доступ к `https://api.telegram.org`, постоянный диск для SQLite и закрытая серверная консоль. Панель хостинга можно открыть в браузере; программы на личном компьютере не обязательны. Конкретный хостинг и стоимость ещё не выбраны. Спящий бесплатный сервис задержит разборы; эфемерный диск потеряет заказы.

На сервере из корня репозитория:

```bash
npm ci --cache /tmp/fw-npm-cache --no-audit --no-fund
npm run bot:start
```

Настройки: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `BOT_ENABLED`, `BOT_BRAND`, `BOT_DB_PATH`. Последний должен указывать на постоянный диск, например `/data/fw-bot/bot.sqlite`. Запускай под отдельным системным пользователем; процесс создаёт файлы с закрытыми правами. Для локальной разработки необязательно использовать `.env.bot` по образцу `.env.bot.example`; этот файл исключён из Git. Не используй префикс `VITE_` для секретов: он предназначен для публичного кода сайта.

Пилот использует long polling, открытый HTTP-порт и webhook ему не нужны. Существующий webhook бот не удаляет: запуск остановится, чтобы не перехватить чужое развёртывание. Другой экземпляр на той же базе заблокирован арендой процесса; после аварийного завершения она истекает за 3 минуты. Один токен не должен работать с несколькими независимыми базами.

## Подключение первых заказов оператором

Для живого теста с двумя собственными аккаунтами сначала зарегистрируй один как эксперта, затем создай **тестовый** заказ. Его личную ссылку открой со второго аккаунта на роль клиента:

```bash
npm run bot:admin -- order:create --expert 1001 --title "Тест бота — без оплаты" --test
```

Флаг `--test` доступен только оператору в серверной консоли. Такой заказ помечен «Демо · без оплаты», имеет нулевую стоимость и никогда не записывает оплату. Трек для него необязателен: можно отправить короткое пробное голосовое. Подтвердить банковский платёж по тестовому заказу нельзя. Все ограничения доступа, один раунд вопросов, срок 72 часа и этапы предложений сохраняются. Запрос следующей услуги явно помечен как пробный. Клиентские команды не могут включить этот режим для обычного заказа.

Это команды в защищённой консоли сервера, не сообщения боту. Числа ниже вымышленные, не запускай их с реальными людьми без замены и согласования. Заказ создаётся неоплаченным. Укажи **цену для клиента, согласованную с конкретным экспертом**; общей цены бот не навязывает.

```bash
npm run bot:admin -- expert:add --id 1001 --name "Демо-эксперт"
npm run bot:admin -- order:create --expert 1001 --title "Тестовый трек" --track "https://example.invalid/private-track" --price 1990 --bot-name example_bot
```

Команда покажет ID заказа и личную ссылку клиента `https://t.me/...?...`. Ссылку передай только этому клиенту: первый открывший привяжет заказ к своему Telegram. Она одноразовая; в базе сохраняется только её хеш. Для реального заказа вместо `example.invalid` нужна доступная эксперту закрытая HTTPS-ссылка на трек. Сервис не скачивает ссылку и не делает её общедоступной; настройки доступа к самому хранилищу задаёт владелец файла. Загрузка аудио с сайта ещё не подключена.

После проверки поступления денег в согласованной платёжной системе/счёте эксперта:

```bash
npm run bot:admin -- payment:confirm --id ID_ЗАКАЗА --receipt-checked
npm run bot:admin -- status
npm run bot:admin -- requests
```

Подтверждение добавит уведомления в очередь, а запущенный бот их доставит. Оплата, привязка клиента и назначенный эксперт нужны одновременно. Сама команда не списывает деньги, не проверяет банк и не создаёт чек. Реальная платёжная модель, чеки, комиссии, возвраты, российские и зарубежные карты требуют отдельного подключения и согласования.

`status` показывает число сообщений в очереди и на повторной доставке, не печатая содержимое. `requests` показывает запросы на следующие услуги; это закрытые данные оператора. Если сообщения долго на повторе, проверь доступ бота к сети и не заблокировал ли получатель бота.

## Надёжность и границы пилота

Заказы, черновики вопросов, состояние диалога, обработанные обновления и исходящая очередь сохраняются в SQLite транзакционно. Повтор Telegram update не создаёт повторного действия. При сетевой ошибке сообщения остаются в очереди; порядок для одного получателя сохраняется, учитывается Telegram `retry_after`. Начало 72 часов привязано к успешному ответу Telegram при отправке голосового, а не к его постановке в очередь. Чтение записи клиентом Telegram не подтверждает.

Абсолютно однократную отправку Telegram не гарантирует: если Telegram принял запись, а ответ потерялся по сети или процесс упал до записи результата, повторная попытка может создать дубликат сообщения. Повторить раунд вопросов, списать деньги или заново отправить предложение старой кнопкой при этом нельзя. При ошибке самой базы процесс останавливается, не пропуская обновление.

База содержит персональные данные и ссылки на треки. Храни её вне публичных файлов и Git, ограничь доступ к серверу, делай резервные копии и согласуй хранение с участниками пилота. Для согласованной копии SQLite используй backup API или останови бота перед копированием базы вместе с WAL. После успешной отправки содержимое исходящего сообщения удаляется из очереди, но вопросы и текст предложения остаются в заказе. Автоматическое удаление по сроку, интерфейс администратора, возвраты, SLA-напоминания, создание заказов с сайта и автоматические платежные уведомления ещё не реализованы.

Перед первым реальным клиентом: выбрать имя и хостинг, безопасно добавить токен, подключить один собственный тестовый Telegram-аккаунт, пройти полный сценарий с настоящей голосовой записью и перезапуском сервиса, согласовать экспертов и условия пилота. Офлайн-тесты не заменяют эту проверку Telegram и сервера.
